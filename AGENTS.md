# AGENTS.md

Source of truth for AI coding agents (Codex, Claude Code, others). `CLAUDE.md` imports this file; edit here only.

## Project
AI Stackprint: cross-platform desktop app (Avalonia 12, .NET 10, C# only, no XAML) that inventories AI apps, orchestrators, plugins, skills, config files and logs on this machine, by level (Project / Local / User / System).

## Commands
- Run: `dotnet run --project src/App`. Build: `dotnet build -v q -nologo` (all projects; `-v q` prints only warnings, errors and the result: keep it). If `AiStackprint.exe` is running, the build cannot overwrite it: ask the user to close it.
- Test: `dotnet test -v q --nologo` (all; App tests take about 2 min), `dotnet test tests/AiStackprint.Core.Tests -v q --nologo` (Core only, no UI), some: `--filter FullyQualifiedName~Part`. New logic in `src/Core/Services` gets tests. UI tests: `[AvaloniaFact]`/`[AvaloniaTheory]` (also for tests that only touch Avalonia types), helpers and seams in `docs/testing.md`; a test never touches the real network, programs or home folder.
- Format: `dotnet format` before committing; keep the build at 0 warnings. Style: dotnet/aspnetcore `.editorconfig` (braces on every `if`/loop, Allman, `_camelCase` private and internal fields, PascalCase constants, `var`, file-scoped namespaces, System usings first, `ConfigureAwait(false)` in Core, not in UI) plus Sonar rules; a justified exception is `#pragma warning disable Sxxx // reason`. Every `.cs` file starts with the MIT license header (`dotnet format` adds it).
- Performance: `dotnet run --project src/App -c Release -- --perf` before and after a change that may affect speed (report in `~/.ai-stackprint/logs/perf-report.txt`; see Performance in `docs/architecture.md`). Coverage: `pwsh build/coverage.ps1`. Screenshots: `pwsh build/test-and-capture.ps1`.
- Release, installers, versions (MinVer: from the git tag only), package versions (`Directory.Packages.props`): `docs/releasing.md`.

## Where things are
Start at `docs/README.md` (which doc answers what). `docs/feature-map.md`: where each feature lives; `docs/recipes.md`: steps for common changes; `docs/architecture.md`: file map (one line per class: search the class name) and one section per area. Read the section you need, never a whole doc: `decisions.md` (agreed product and UI choices) and `design-system.md` (tokens, components) have a heading per page and component.
- `src/Core` (models and services, no Avalonia; services must not depend on UI code, the build enforces it) ← `src/App` (`Ui`, `Program.cs`, `Assets`; builds `AiStackprint.exe`). Tests: `tests/AiStackprint.Core.Tests`, `tests/AiStackprint.App.Tests` (headless).
- Data, embedded in Core: `default/apps.json` (built-in apps; the user's `~/.ai-stackprint/apps.json` holds only `custom.` apps), `default/settings.json` (every setting, default and meaning; the user's file holds only changes), `default/models.json` (generated weekly by `tools/ModelData`: never edit by hand; read through `ModelCatalog`).
- Large files: search, never read whole: `src/App/Assets/logos.json` (57 KB) and `icons.json` (21 KB) (path data, by name), `default/apps.json` (by app id), `default/models.json` (85 KB, by model name), `.editorconfig` (by rule id).

## Rules
- A new app is data in `default/apps.json`: no per-app `if` in `Scanner`. A new plugin manifest format is an `IPluginReader` in `PluginReaders.All`; likewise context rules (`IContextRule`, `ContextBudget.Rules`) and live limits (`ILimitProvider`, `LimitProviders.All`).
- Network: nothing is sent about the user, and each feature calls only its own host:
  - Live limits: only for apps the user turned on (with a consent dialog), at most one call per app per refresh interval (one minute minimum). Tokens stay in memory: never shown, logged, saved or refreshed; credential files are opened read-only.
  - Update check (`UpdateCheck`, api.github.com) and model data (`ModelDataUpdate`, this repo's `default/models.json` with `If-None-Match`): off until turned on in Settings › Updates or Check now; at most once a day. The update check never downloads or installs; drafts and pre-releases are ignored; show the version with `UpdateCheck.Label`, compare with `UpdateCheck.Current`.
  - Benchmarks (`BenchmarkUpdate`, artificialanalysis.ai, free language-model list): off until the user turns it on and saves their own key; at most once a day or on Refresh now. The key (`UiState.BenchmarkKey`, state.json) goes only in the `x-api-key` header: never exported, shown again, logged or put in a message or URL; import never turns `benchmarksEnabled` on. Keep their credit on the Models chart and in Credits.
  - Downloads are saved (`cache/`) only when valid; the last good copy stays on any failure.
- Tray: off by default; turning on "Keep running in the tray" is the user's confirmation. One process (no helper exe); a second start hands over through `SingleInstance`. The login entry (`LoginItem`) exists only while the tray and "Start at login" are on, and uninstall removes it. Alerts go only to this computer's notifications; the Windows app id and `aistackprint:` link (HKCU\Software\Classes) exist only while alerts and the tray are on. A link only hands `show <page>` or `pause` to the running copy: never run anything else from it.
- The scanner is read-only. Only `SkillManager`, `PluginManager`, `ConfigEditor`, `LogTrash` and `DataImport` change things, after the user confirms in a dialog (`DataImport` and the AGENTS.md export after a preview; import copies each file to `backups/import-…` first; `LoginItem` and `Notifier` write only their own entries, per their switches). Removed skills go to the backups folder, never deleted; saved config files are backed up first and refused if they changed on disk; plugin changes run the app's own CLI without a shell, with whitelisted arguments; log deletes move only listed log files to the Recycle Bin/Trash.
- UI: every API call or long operation shows `Busy` (at once; a refresh keeps the last data with a small spinner; errors show a message and Retry). Colors only from `Theme` through `W.Themed` (no hex elsewhere). Text through `W.Txt`/`W.Title`/`W.Size` with `W.Body`/`W.Emphasis`/`W.Heading` weights (fonts are never bundled or downloaded). Sizes only from `src/App/Ui/Tokens.cs` (`DesignTokenTests` fails on literals); titled cards use `W.Section`. Levels are listed System, Local, Project, User (`Levels.Order`). AvaloniaEdit + TextMate only inside `CodeView`.
- A control kept in a field and shown on a rebuilt page is taken from its old parent first (`.Free()`), or the app crashes; a view's `Leave()` replaces such controls and drops callbacks, or the old page stays in memory. To find "the same" skill or plugin after a rescan use `ItemBrowser.Same`, not `==`.
- Settings: a new one goes in `default/settings.json` with its default and a comment (the only place defaults are written) and a `Settings` property; defaults via `SettingsStore.Defaults()`, never `new Settings()`; remembered values that are not preferences go to `UiState` (state.json). Before 1.0 settings and data files may change structure freely (drop dead keys on load: `SettingsStore._obsoleteKeys`); from 1.0 any structure change bumps the file's version with an upgrade step (`VersionedJson`).
- Catch only expected IO/JSON exceptions. Fatal errors go to crash.log (`CrashLog`); `CrashNotice` offers a prefilled GitHub issue with the home folder and user name removed; the app sends nothing itself.
- One class per concern, files under about 250 lines (split as `Class.Topic.cs`). A new or renamed file gets its line in the file map (`docs/architecture.md`); a new feature its row in `docs/feature-map.md`.
- Commits (and squash-merged PR titles) are Conventional Commits (`feat:`, `fix:`, `perf:`, `refactor:`, `test:`, `build:`, `ci:`, `docs:`, `chore:`); they become the release notes.
- Before finishing: `dotnet build -v q -nologo`, and report what could not be verified.
- Do not guess: paths for apps without documented locations are best-effort; mark them with a `notes` field in the JSON.
